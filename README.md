# 药物经济学工作台 · PE-Workbench

**让药物经济学工作的每一步可理解、可追溯、可审查。**

一个面向药物经济学 / 卫生技术评估（HEOR/HTA）工作者的本地化工作台。把"方案-证据-建模-分析-报告-申报"这条链变成**受控工作流**：谁在哪个步骤做什么、要不要电子签名、改过没有、能不能复现——全部写进界面，全部留痕在审计链里。

---

## 一、为什么这样设计

市面上的药物经济学工具几乎全是"计算器"：TreeAge、Excel 模型、R 脚本。它们能算出漂亮的 ICER，但回答不了评审人真正会问的问题——**数字从哪来、谁批准过、改过没有、能不能复现**。本工作台不替代建模软件，它管的是建模软件不管的那层：**受控流程与账户权限**。

五个核心判断：

**1. 药物经济学工作形态高度同构。**
方案评审、系统文献综述、间接比较、效用研究、成本测算、模型验证、预算影响、报告核查——本质都是"一条受控记录 + 一串有角色与签名门槛的步骤"。所以领域是数据不是代码：**加一条新流程只需往 `seed/workflows/` 放一个 JSON 文件**。

**2. 控制做进机制，不能靠自觉。**
审计追踪用哈希链实现（只可追加，改库被触发器拦截）；电子签名强制两个独立识别要素（密码 + 动态口令/一次性挑战码）；所有记录修改强制填写理由；数据问题的提出人不能自己关闭；模型开发者不能自己发布自己的模型——这些是**代码强制**的。

**3. 职责写在图上，不放在悬浮提示里。**
领域页第一屏就是工作流程图：每步下面直接列出负责岗位、签名门槛与操作指引。三态权限矩阵（允许 / 不允许 / ⚠ 有约束）如实呈现"界面说允许、内核仍会拒绝"的情况——例如 HEOR 负责人持有 `record.close`，但内核仍拒绝他关闭自己起草的记录。

**4. 检查就绪度常态可见。**
把 CHEERS 2022、中国药物经济学评价指南（2020）、ISPOR-SMDM 模型验证七问、ALCOA+ 变成可逐条判定的检查表；负面判定**必须**附客观证据；未关闭的严重缺陷、超期记录、文件审核欠账汇成一个带**具名阻碍项**的就绪度评分。

**5. 工作流自己跑，不能等人来看。**
后台监控进程定时扫描超期记录并升级、提示文件定期审核到期、提醒未关闭的严重缺陷——不需要任何人打开页面。

## 二、快速开始

```
双击  PEWorkbench.exe      ← 推荐：自己的桌面应用窗口
或    双击  start.bat      ← 备用：控制台 + 服务
```

**`PEWorkbench.exe` 是原生 Windows 桌面窗口**（自己的标题栏、任务栏图标、托盘图标），不是浏览器窗口，也不依赖用户浏览器：

- 内嵌 **WebView2**（微软随 Windows 更新的系统组件，与 Teams/VS Code 同类的"应用内网页视图"）在窗口内渲染工作台——窗口关闭时收进托盘，托盘菜单可：打开窗口 / 查看服务日志 / 重启服务 / 退出
- 本地 Node 服务作为隐藏后台进程自动拉起；窗口退出时通过**令牌保护的优雅关闭端点**（`POST /api/shutdown`）停服——审计链冲洗、后台监视进程先停止，不留孤儿进程
- 首次启动自动完成全部初始化（约 5 秒）：
  1. 创建数据库与审计链密钥
  2. 加载配置库（10 类工作流、4 张检查表 71 项要求、7 个专业领域）
  3. 创建 11 个演示身份（统一密码 `PE-Demo-2026!`）
  4. **生成演示数据集**：虚构肿瘤新药 **PE-001** 的医保准入成本-效用分析全流程（方案、SLR、间接比较、效用、成本、模型、BIA、CEA 报告、数据问题、变更控制，共 10 条记录）
  5. 校验审计链完整性

第二次启动只重载配置库，不重复生成。

- `start.bat` — 若存在 `PEWorkbench.exe` 则启动桌面窗口；否则控制台模式（`node src/server.js`）
- `start.bat 8810` / `PEWorkbench.exe --port 8810` — 换端口
- `stop.bat` — 停止实例
- 环境变量：`PE_BUILTIN_ACCOUNTS=0` 关闭演示账号（同时不生成演示数据）；`PE_MONITOR=0` 关闭后台监控

重建桌面启动器（需要联网一次，仅构建期）：`npm run build:desktop`（编译用 Windows 内置的 .NET Framework C# 编译器，产物 `PEWorkbench.exe` + 3 个 WebView2 DLL，输出到项目根与 `dist/desktop/`；`PEWorkbench.exe --shot 路径.png` 可自检验证窗口渲染与优雅关闭）。

> **演示身份共用统一密码是标注的风险**：不符合"账号唯一"的账户安全要求，界面有醒目警示。真实部署必须 `PE_BUILTIN_ACCOUNTS=0` 并经由「用户与权限」为每人创建独立凭证。

### 打开后你会看到什么

**第一屏是身份选择**：11 张身份卡（HEOR 负责人、研究员、建模分析师、证据综述研究员、生物统计师、临床顾问、申报专员、HEOR QA、数据管理员、协调员、外部评审专家），每张卡写明岗位、职责、所能进入的领域与"看完能理解什么"。密码是**真的校验**的。

**登录后七个领域**（研究设计与方案 RSD / 证据检索与合成 EVS / 健康效用与结局 OUT / 成本测算 CST / 经济建模 MDL / 分析与解读 ANA / 报告与申报 RPT），点任意领域卡，**第一屏就是该领域的工作流程图**：横向步骤、每步下方是负责岗位、签名门槛与指引。

**我的待办**按后果轻重排序（严重优先 → 需签名优先 → 超期优先），并明确标出哪些需要电子签名、超期几天；底部说明这个岗位**不能**做什么——操作者看到空页签时不会怀疑系统坏了。

**分析工具**：受审计的 ICER / 预算影响 / QALY 计算器——每次运算记录输入、输出与操作者，报告里的每个数字都可回溯到一次计算记录。

**自查与检查表**：CHEERS 2022（28 项）、中国指南（16 项）、ISPOR-SMDM 模型验证（13 项）、ALCOA+ 分析数据完整性（14 项），可对具体报告/模型启动评估、逐条判定并一键转为数据问题或变更控制记录。

界面截图见 [docs/screenshots/](docs/screenshots/)（18 张：身份选择、领域流程图、工作流责任链、仪表盘、待办、评估、计算器、审计等）。

### 用户端操作体验（借鉴同类软件的实践）

- **全局搜索（Ctrl+K 或 `/`）**：顶栏随时搜索记录、文件、流程与人员，回车直达；结果按你的权限过滤
- **首次登录三步引导**：指出「领域与流程 → 我的待办 → 分析工具」各在哪里、看完能得到什么
- **记录进度条 + 下一步行动卡**：详情页顶部显示全流程步数进度；"下一步"卡片写明当前步骤、责任岗位、签名要求与期限，一个按钮直达表单；职责不符时明确说明"这一步在等谁"
- **创建向导**：选流程即预览"创建后从哪一步开始、共几步、几处需签名、SLA 多少天"；创建成功的提示带"查看记录 →"快捷动作
- **ICER 交互式调参预览**（借鉴 R/Shiny HTA 的交互式参数探索）：拖动价格滑杆，Δ成本 / ICER / INMB / 经济性结论即时变化——预览只在本地计算，点"计算并留痕"才写入审计追踪
- **空状态引导**：空库时记录页给出"从这里开始三件事"的操作指引
- **可点击的仪表盘 KPI**：每个数字直达对应的筛选列表或审计页
- **暗色模式**（跟随系统）与**打印样式**：报告与记录可直接打印或存 PDF 作为纸面证据
- **Toast 反馈**：所有操作即时反馈，错误信息具体可操作

## 三、具体工作流（10 条）

| 编码 | 工作流 | 关键步骤（示意） |
|---|---|---|
| `PROTO` | 研究方案与健康经济学分析计划（HEAP） | 起草(PICO) → 方法学评审 → **批准✍** → 修订 → QA 归档 |
| `SLR` | 系统文献综述 | 检索策略确认 → 双重筛选 → 数据提取 → 质量评估 → 证据综合 → **QA 审阅✍** → 关闭 |
| `ITC` | 间接治疗比较 / 网络荟萃分析 | 方案(传递性论证) → 分析运行 → 一致性检验 → 报告 → **统计学审核✍** → 关闭 |
| `UTL` | 效用与健康结局研究 | 数据收集 → 效用评分(价值集) → 映射验证 → **临床合理性审阅✍** → 关闭 |
| `CST` | 成本分析研究 | 资源清单 → 单价核实(可溯源) → 核算(视角口径) → 敏感性 → **方法学审阅✍** → 关闭 |
| `MODEL` | 经济模型开发与验证 | 结构设计 → **结构评审✍** → 参数集 → 编码 → **内部验证(ISPOR-SMDM 七问)** → **独立外审✍** → **版本发布✍** → 归档 |
| `BIA` | 预算影响分析 | 人群规模估计 → 市场份额情景 → 测算(3-5年) → **独立复核✍** → 关闭 |
| `CEA` | 成本-效果评估报告 | 结果汇总 → 增量分析(ICER/INMB) → 阈值解读 → **CHEERS 合规核查** → **批准✍** → **对外提交✍** → 归档 |
| `DISS` | 数据完整性问题 | 识别分级 → 偏倚影响评估(方向/大小) → 纠正与预防(根本原因) → **QA 独立关闭✍** |
| `CHG` | 变更控制（模型/方法/参数） | 申请 → 影响评估(结论方向?) → **批准✍** → 实施(新版本) → **验证✍** → 关闭 |

✍ = 电子签名步骤（双要素：密码 + 一次性挑战码/动态口令）
每一条流程的 JSON 定义见 `seed/workflows/`，含步骤角色门槛、必填字段、签名含义与操作指引（guidance）。

## 四、账户与权限体系

**13 个岗位**（`src/core/rbac.js`），40+ 项权限，另有 12 条**代码强制约束**（`src/domain/constraints.js`）：

| 岗位 | 权限要点 |
|---|---|
| 系统管理员 | 全部技术权限，**不能**作为分析记录的唯一批准人 |
| HEOR 负责人 | 批准方案/模型/报告/申报的最终签字人 |
| 药物经济学研究员 | 起草、成本/效用分析、ICER 计算 |
| 建模分析师 | 模型开发与内部验证（不能自己发布） |
| 证据综述研究员 | SLR / 间接比较 |
| 生物统计师 | NMA、一致性检验、模型验证、不确定性 |
| 临床顾问 | 临床合理性审阅（模型结构、结局、效用） |
| HTA / 医保申报专员 | 对外提交（提交动作本身签名留痕） |
| HEOR 质量保证专员 | 独立核查（CHEERS）、关闭数据问题、外审模型 |
| 数据管理员 | 原始数据保管、成本目录、发起数据问题 |
| 项目协调员 | 排期与文档流转，只读 |
| 外部评审专家 | 只读、**限时**（到期自动失效），每次查看被审计 |
| 只读用户 | 只读 |

核心强制约束（全部服务端执行）：
- **独立关闭**：数据问题提出人不能关闭；方案/模型/报告起草人不能批准自己的产出
- **三态矩阵**：权限矩阵的"⚠ 有约束"逐项标明拒绝原因与方法学依据
- **可见性按职能不按级别**：QA 跨领域可见，系统管理员反而看不到他人人员信息
- **负面判定必须有客观证据**（≥10 字），无证据的"存在缺陷"在入口被拦住
- **已关闭记录只读**；任何变更走 `CHG` 并产生新版本

## 五、核心能力

| 能力 | 实现 |
|---|---|
| 哈希链审计追踪 | SHA-256 + HMAC 链，只可追加，触发器拦截 UPDATE/DELETE，校验定位到断点 |
| 双要素电子签名 | 密码 + 一次性挑战码/TOTP，签名显示姓名、时间、含义、理由 |
| 修改理由强制 | 所有记录修改必须填写理由；取消记录至少 10 字 |
| 历史重建 | 任一记录的历史版本可从审计链单独重建 |
| 配置驱动工作流 | 10 条流程全部为 JSON 定义，改文件即生效 |
| 后台监控 | 超期记录升级、文件定期审核提醒、严重缺陷提醒（幂等） |
| 受审计计算器 | ICER/INMB、预算影响、QALY 贴现——每次计算全量留痕 |
| 就绪度评分 | 严重缺陷(×25)、超期记录、审核欠账、审计链完整性 → 具名阻碍项 |
| 会话控制 | 空闲超时、绝对时限、失败锁定，登出原因明确告知 |
| 限时外部评审 | access_expires_at 登录与每请求双重校验 |

## 六、环境与零依赖

只需要 **Node.js 22.5+**（依赖内置 `node:sqlite`），**零第三方依赖**，断网可运行。桌面窗口用 Windows 自带的 Edge（`--app` 模式）；找不到时退回默认浏览器。

这不是技术洁癖：在受控环境里每个第三方包都需要供应商评估与变更控制——零依赖意味着验证范围极小。

## 七、数据与备份

所有数据在 `data/`：`pe.db`（业务+审计）与 `audit-chain.key`（链密钥）。**两者必须一起备份**——密钥丢失后审计链永远无法校验。

```bat
node scripts\backup.js             :: 备份
node scripts\verify-audit.js       :: 校验审计链
node scripts\audit-coverage.js     :: 各领域内容覆盖审计
node scripts\seed.js               :: 重载配置库
node scripts\seed-demo.js          :: 重新生成演示数据（空库时）
node scripts\pe-screenshot.js      :: CDP 界面验证与截图（需先启动服务）
```

## 八、自检

```bat
node test\run-all.js
```

51 项检查，2 个套件：`core`（30 项：审计链/权限/工作流引擎/签名/计算器/检查表/文件控制）与 `e2e`（21 项：真实 HTTP 会话、步骤完成、角色门 403、双要素签名、吊销会话等）。

## 九、验证与免责

**本软件是辅助工具**：不替代专业判断、不替代卫生技术评估结论、不构成法规符合性判定。检查表条目为依据公开规范拟定的自查断言（CHEERS 2022 / 中国药物经济学评价指南 2020 / ISPOR-SMDM / ALCOA+），正式申报前请与各规范原文及主管部门要求逐项核对。演示数据中企业、人名、药品（PE-001）与数字全部虚构。
